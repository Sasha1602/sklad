# Склад проката

Сайт и приложение для учёта прокатного оборудования (свет, звук, видео): склад, мероприятия и календарь, команда на выезд, графики сотрудников, комплекты и QR-наклейки, быстрый прокат, учёт недостач, push-уведомления, работа без связи. Вход по почте, роли сотрудников, изменения видны всем сразу, журнал «кто что поменял».

- **Сайт** — обычные файлы, хостится на GitHub Pages бесплатно. Ставится на телефон как приложение (Android и iPhone).
- **База и вход** — [Supabase](https://supabase.com), бесплатный тариф. Права проверяет сама база, поэтому их нельзя обойти через браузер.

## Что в архиве

| Файл / папка | Что это |
|---|---|
| `index.html`, `app.js`, `style.css` | Сам сайт |
| `config.js` | Ваши ключи. **В архиве обновлений его нет — не заменяйте свой** |
| `sw.js`, `manifest.webmanifest`, `icons/` | Приложение на телефоне, работа без связи, уведомления |
| `vendor/` | Библиотеки: Supabase, генератор QR, сканер QR (чтобы не зависеть от CDN) |
| `supabase/*.sql` | Настройка базы — запускаются в SQL Editor |
| `supabase/functions/notify/index.ts` | Функция отправки push-уведомлений |

## Роли

| Роль | Что может |
|---|---|
| Ожидает | Зарегистрировался, ничего не видит, пока админ не назначит роль |
| Просмотр | Видит склад, мероприятия и журнал |
| Кладовщик | Меняет количество факт, состояние, статус, примечание; отгружает и принимает возврат; создаёт быстрый прокат; отмечает «Нашёлся» |
| Менеджер | Добавляет, редактирует и удаляет оборудование, мероприятия и комплекты; бронирует; ставит команду; списывает потери |
| Администратор | Всё то же + назначает роли (вкладка «Люди») |

**Первый зарегистрированный пользователь автоматически становится администратором.** Зарегистрируйтесь первым сами, сразу после настройки.

## Установка с нуля (≈20 минут)

### 1. База в Supabase

1. <https://supabase.com> → **New project**. Регион — ближайший (например, Frankfurt). Пароль базы сохраните у себя.
2. Слева **SQL Editor** → **New query** → вставьте файл целиком → **Run** → должно быть «Success». Файлы строго по порядку:

| № | Файл | Что добавляет |
|---|---|---|
| 1 | `schema.sql` | Позиции, роли, журнал |
| 2 | `02_events.sql` | Мероприятия и календарь |
| 3 | `03_crew.sql` | Команда на выезд |
| 4 | `04_schedule.sql` | Графики сотрудников |
| 5 | `05_kits.sql` | Комплекты (кейсы) |
| 6 | `06_quick.sql` | Быстрый прокат |
| 7 | `seed.sql` | Ваши 64 позиции из инвентаризации. **Один раз**, иначе задвоятся |
| 8 | `07_push.sql` | Уведомления — по инструкции ниже, можно позже |
| 9 | `08_losses.sql` | Учёт недостач и списание |
| 10 | `09_calendar.sql` | Календарь телефона по ссылке и подписка «мои выезды». После настройки уведомлений |
| 11 | `10_apns.sql` | Push в приложение для iPhone и push «Вас поставили на выезд». После настройки уведомлений |
| 12 | `11_venues.sql` | Справочник площадок и залов. Площадки из уже созданных мероприятий попадут туда сами |
| 13 | `12_shifts.sql` | Виды смен и отметки по дням для приложения «Смены» (сайт и «Склад» их учитывают) |
| 14 | `13_day_notes.sql` | Личные заметки на дни в «Сменах» — видит только автор, сайт и «Склад» их не читают |
| 15 | `14_shift_company.sql` | Компания у смен — её сокращение в кружке календаря «Смен» |
| 16 | `15_smeny_plus.sql` | Зарплата и обмены сменами в «Сменах» (личные), ответ «Смогу / Не смогу» на выезд |

Все файлы, кроме `seed.sql`, можно запускать повторно — ничего не сломается.

### 2. Вход

1. **Authentication → Sign In / Providers → Email** — включено. «Confirm email» можно выключить: тогда регистрация сразу ведёт на экран «ждём одобрения», без писем.
2. **Authentication → URL Configuration** (после шага 4): **Site URL** и **Redirect URLs** — адрес сайта, например `https://ВАШ-ЛОГИН.github.io/sklad/`.

### 3. `config.js`

Supabase → **Project Settings → API** (или кнопка **Connect**): **Project URL** и **publishable** ключ (`sb_publishable_…`, или старый anon).

```js
window.SKLAD_CONFIG = {
  SUPABASE_URL: "https://abcdefgh.supabase.co",
  SUPABASE_KEY: "sb_publishable_…",
  TITLE: "Склад проката",
  PUSH_PUBLIC_KEY: ""
};
```

- Каждая строка — **внутри** `{ … };`, между строками запятые, после последней запятой нет. Строка за пределами скобок ломает файл, и сайт пишет «Сайт ещё не подключён».
- Этот ключ публичный, его можно хранить на GitHub. **Ключ `service_role` / `secret` не вставляйте никогда** — он обходит все права.

### 4. GitHub Pages

1. <https://github.com> → **New repository**, например `sklad`.
2. **Add file → Upload files** → перетащите всё содержимое папки (`index.html`, `app.js`, `style.css`, `config.js`, `sw.js`, `manifest.webmanifest`, папки `icons`, `vendor`, `supabase`) → **Commit**.
3. **Settings → Pages** → Source: **Deploy from a branch**, **main**, **/ (root)** → **Save**.
4. Через 1–2 минуты сайт будет на `https://ВАШ-ЛОГИН.github.io/sklad/`. Впишите адрес в шаг 2.2.

### 5. Первый вход

1. Откройте сайт → **Регистрация** → вы администратор.
2. Сотрудники регистрируются по той же ссылке и попадают в «Ожидает».
3. Вкладка **Люди** → назначьте роль. У сотрудника страница откроется сама.

## Как пользоваться

### Сегодня

Открывается первой. Сверху — что требует внимания (просрочки, неотмеченные отгрузки, недостачи), затем:

- **«Уезжает сегодня»** и **«Уезжает завтра, чт 23 окт»** — отдельные карточки, чтобы не путать дни;
- что на выезде и когда вернётся;
- **«Мои следующие выезды»** — только те, что ещё не показаны выше (без повторов). На своих мероприятиях отметка «вы едете» или «вы ответственный»;
- кто сегодня работает по графику, что в ремонте;
- кнопки «Быстрый прокат», «Включить уведомления», «Установить приложение».

### Мероприятия и календарь

1. **Создать** (менеджер): «+ Мероприятие» или кнопка под выбранным днём. Даты — от монтажа до демонтажа: на все дни оборудование бронируется.
2. **Оборудование**: у каждой позиции «свободно X из Y» с учётом других мероприятий. Не хватает — подсветка и где занято.
3. **Отгрузить** (кладовщик) → проверить погруженное → подтвердить. Статус «На выезде».
4. **Принять возврат** → пересчитать → подтвердить. Не вернувшееся становится недостачей.
5. **Команда** (менеджер): «+ Человек» — сотрудник с аккаунтом или без (имя, телефон с маской +7 (9xx) xxx-xx-xx). Конфликты по датам и сменам подсвечиваются.
6. **«Только мои»** над календарём — мероприятия, где вы ответственный или в команде. Под календарём список «Ближайшие».
7. **«Копировать список»** — команда с телефонами и оборудование по кейсам, готово для мессенджера.
8. **«В календарь»** — одно мероприятие в календарь телефона или Google Календарь, напоминание накануне вечером. Там же **«Подписаться: мои выезды»** — все выезды сотрудника сами появляются в календаре телефона и обновляются; **«Подписаться: смены основной работы»** — отдельный календарь со сменами из «Графика» (с учётом отпусков и «недоступен», начиная с даты смены в графике), со своим цветом; напоминание срабатывает даже без интернета. Менеджеру доступно «все мероприятия». Нужен `09_calendar.sql` (см. ниже).

**Площадки и залы.** В форме мероприятия поле «Площадка» подсказывает площадки из справочника; если у площадки есть залы — рядом появляется выбор зала. Новую площадку, вписанную вручную, менеджер добавляет в справочник автоматически при сохранении. Кнопка **«Площадки»** над календарём — справочник: адрес (открывается в Яндекс Картах из карточки мероприятия), контакт, заметки (въезд, питание, тишина после 23:00), залы с заметками (размеры, подвес). Всё это видно в карточке мероприятия. Меняют справочник менеджер и администратор.

**Площадки из интернета.** В окне «Площадки» впишите город и нажмите «Найти в интернете»: из открытых карт OpenStreetMap подтянутся рестораны, банкетные залы, кафе, клубы, ДК в городе и отели, базы отдыха в 30 км — с адресами и телефонами, где они указаны. Отметьте нужные → «Добавить выбранные». Кроме того, при создании мероприятия поле «Площадка» подсказывает заведения выбранного города «из интернета» — выбранное само попадёт в справочник с адресом. Данные хранятся на устройстве неделю. Залов внутри заведений в открытых данных нет — их дописывают вручную в карточке площадки. Если заведения нет на карте, его можно добавить на openstreetmap.org — через пару дней оно появится и здесь.

Ссылка на мероприятие: `…/sklad/#ev-12`.

### Графики сотрудников

«Люди» → «График» у сотрудника (или сам сотрудник — клик по своему имени вверху).

- **Смены на основной работе**: сколько дней работает / отдыхает и дата любой смены («сутки через трое» — 1 и 3).
- **Исключения**: «отпуск на основной работе» — смены не считаются; «недоступен» — занят совсем.
- Таблица **«Кто свободен»** на 3 недели; красная клетка — стоит на мероприятии в день смены.

### Комплекты и QR

- **Склад → Комплекты** — кейсы с постоянным составом. «Взять всё из места…» заполняет состав из места хранения. В мероприятии «+ Комплект» добавляет весь состав.
- **Склад → QR-этикетки** — отметьте позиции/комплекты, выберите формат → **«Печать»** → «Распечатать» (свой принтер) или **«Скачать PDF»** (точный масштаб 1:1 — для копицентра или типографии; на телефоне откроется «Поделиться»). «По количеству» — наклейка на каждую единицу.
  - **А4 на 24** (QR ~33 мм) — кейсы и крупные приборы; **на 40** (~21 мм) — почти всё; **на 65** (~19 мм) — мелочь.
  - **Флажок на провод** — полоска «QR | обмотка | название». Середину оборачивают вокруг кабеля, концы склеивают между собой: QR остаётся плоским и читается. Длина обмотки — по толщине кабеля (до 6 / 10 / 15 мм). Печатать на целом самоклеящемся листе, резать по серым линиям, сгибать по пунктиру; сверху можно надеть прозрачную термоусадку.
- **Сканирование** при отгрузке и возврате: «Обнулить и считать сканером». Наклейка комплекта засчитывает весь состав. Без камеры — впишите код (I-12, K-3). Обычная камера телефона по наклейке открывает карточку позиции.
- Камера работает в Safari и Chrome; во встроенных браузерах мессенджеров может не работать.

### Быстрый прокат и сборка сканером

- **«Быстрый прокат»**: кому, телефон, когда вернут — и сразу сборка.
- **Сборка**: каждый скан +1, наклейка комплекта — весь состав; можно вписать код или начало названия («dmx 10»). «Отгрузить» — сразу на выезд; «Сохранить» — позже.
- «Собрать сканером» есть в любом запланированном мероприятии — для сумок к большим выездам.
- Кладовщик меняет список, пока мероприятие не отгружено; после — только менеджер.

### Недостачи

- **Возврат кейса**: в «Принять возврат» отсканируйте наклейку кейса — откроется его состав со счётчиками с нуля. Сканируйте содержимое или нажмите «Всё на месте».
- Недостача висит в карточке мероприятия и на «Сегодня», пока её не разберут:
  - **«Нашёлся»** (кладовщик и выше) — вернули позже;
  - **«Списать»** (менеджер) — потеряно: количество на складе уменьшается, запись в журнале.
- **Неполный кейс** — пока недостача не разобрана, в «Комплектах» и при добавлении кейса видно, чего в нём нет и после какого мероприятия.

### Ответ на выезд и подсказки по сменам

- Сотрудник, которого поставили на выезд, в карточке мероприятия видит кнопки **«Смогу» / «Не смогу»** (с причиной). То же — в приложениях «Склад» и «Смены».
- В команде у каждого видно: **сможет**, **не сможет** (строка подсвечена) или **ждём ответ**. Менеджерам и ответственному приходит уведомление.
- По сменам основной работы видно время: «Сутки · RU 08:00–08:00». Подсказки: **«смена до 20:00 — сможет только после»**, **«после ночной смены, свободен с 08:00»** — в команде, при выборе человека и в «Кто свободен» (жёлтые клетки).
- Нужен `15_smeny_plus.sql` и обновлённая функция `notify` (для уведомления о ответе).

### Приложение и работа без связи

- **iPhone**: сайт в **Safari** → «Поделиться» → **«На экран «Домой»»**.
- **Android**: сайт в **Chrome** → «Установить приложение» на экране «Сегодня» (или ⋮ → «Установить приложение»).
- Обновляется само вместе с сайтом.
- **Без связи** показываются последние загруженные данные. Количество, состояние, статус, отгрузка и возврат копятся в очереди («в очереди: N») и уходят, когда связь появится. Новые мероприятия, позиции и комплекты без связи не создаются.

## Push-уведомления (настройка один раз)

Что приходит: **«Завтра выезд»** (команде и ответственному, в 18:00 МСК), **«Не вернули вовремя»** и **«Отгрузка не отмечена»** (менеджерам, в 18:00), **«Не вернулось с мероприятия»** и **«… требует ремонта / не найден»** (менеджерам, сразу).

1. **Ключи.** Сайт → администратор → «Люди» → «Уведомления» → **«Сгенерировать ключи»**. Используйте **один** набор ключей везде — если сгенерировали заново, замените все значения.
2. **config.js**: публичный ключ в `PUSH_PUBLIC_KEY: "…"` (внутри скобок!).
3. **Функция.** Supabase → **Edge Functions** → Deploy a new function → **Via Editor** → вставьте `supabase/functions/notify/index.ts` → Deploy.
   - Supabase может дать функции своё имя (например, `swift-function`) — это нормально. **Адрес берите со страницы функции**, он понадобится в шаге 5.
   - В настройках функции **выключите** «Verify JWT with legacy secret» / «Enforce JWT verification».
4. **Секреты.** Edge Functions → **Secrets**: `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` (из шага 1) и `NOTIFY_SECRET` (из шага 5). Вставляйте без кавычек и пробелов.
5. **База.** SQL Editor → запустите `07_push.sql` как есть (создаст таблицы и расписание). Если ругается на `pg_cron` / `pg_net` — Database → **Extensions** → включите и запустите снова. Затем впишите адрес функции и создайте секрет:
   ```sql
   update private.notify_config
      set url = 'https://ВАШ-ПРОЕКТ.supabase.co/functions/v1/ИМЯ-ФУНКЦИИ',
          secret = md5(random()::text || clock_timestamp()::text)
    where id = 1
   returning secret;
   ```
   Скопируйте полученный `secret` в Secrets как `NOTIFY_SECRET`.
6. **Каждый сотрудник** на «Сегодня» нажимает **«Включить уведомления»**. На iPhone — только из установленного приложения (iOS 16.4+).
7. **Проверка:** `select private.notify_test('ваша@почта.ru');` — через несколько секунд «Уведомления работают ✓».

### Приложение для iPhone

Нативное приложение — отдельный архив `Sklad-iOS.zip` (инструкция внутри). Push в него отправляет та же функция: добавьте в Secrets `APNS_KEY` (содержимое `.p8`), `APNS_KEY_ID`, `APNS_TEAM_ID`, `APNS_BUNDLE_ID` и запустите `10_apns.sql`. Без этих секретов функция работает как раньше — только сайт.

`10_apns.sql` также добавляет уведомление **«Вас поставили на выезд»** — приходит сотруднику, когда менеджер добавляет его в команду мероприятия (и на сайт, и в приложение).

### Календарь по ссылке

Календарь отдаёт та же функция, что и уведомления. После шагов 1–5 выше: обновите функцию (вставьте новый `index.ts` → Deploy) и запустите `09_calendar.sql` — в конце он покажет адрес функции. Если функцию потом переименуете, запустите файл ещё раз.

На iPhone после подписки: **Настройки → Календарь → Учётные записи → Подписные календари → «Склад…» → выключите «Удалить напоминания»**, иначе iPhone уберёт напоминания. Календарь обновляется примерно раз в час; при плохой связи остаются последние загруженные события.

Ссылка личная. Если она попала не туда — удалите строку сотрудника в Table Editor → `cal_tokens`, при следующем открытии «В календарь» создастся новая (старую подписку придётся удалить и подписаться заново).

### Если не приходят

Ответы функции:
```sql
select created, status_code, content from net._http_response order by created desc limit 3;
```
- **401** — включена проверка JWT у функции → выключите (шаг 3).
- **403 forbidden** — секрет в базе и в Secrets разный. Сравните отпечатки: в SQL
  ```sql
  select encode(sha256(convert_to(secret,'UTF8')),'hex') from private.notify_config;
  ```
  и в Edge Functions → Secrets (там показывается такой же SHA-256 у `NOTIFY_SECRET`). Не совпадают — повторите шаг 5 и вставьте секрет заново.
- **404** — неверный адрес функции в `notify_config`.
- **500** — не хватает или испорчены VAPID-ключи в Secrets; текст ошибки в `content` и в логах функции.
- Пусто — `07_push.sql` не запущен или адрес ещё с `ВСТАВЬТЕ_…`.

## Обновление работающего сайта

1. В репозитории **Add file → Upload files** → перетащите новые `index.html`, `app.js`, `style.css`, `sw.js`, `manifest.webmanifest`, папки `icons`, `vendor` → **Commit**. Старые заменятся.
2. **`config.js` не загружайте** — в архиве обновлений его специально нет, ваши ключи останутся.
3. Новые SQL-файлы из `supabase/` — один раз в SQL Editor.
4. Через 1–2 минуты обновите страницу. Приложение на телефоне подтянет новую версию само при следующем открытии со связью.

## Связь и блокировки

- Индикатор вверху: зелёный — данные обновляются сразу; **«нет связи»** — живое обновление не работает, но сайт работает из сохранённых данных и очереди.
- У части мобильных операторов в России адрес `supabase.co` блокируется: календарь и склад пустые или «нет связи». Сейчас помогает VPN. Надёжное решение — перенос базы на российский сервер (отложено).

## Полезно знать

- **Security Advisor** в Supabase не должен показывать предупреждений. Если базу создавали старой версией и видите «Can Execute SECURITY DEFINER Function» — один раз запустите `supabase/fix_security.sql`.
- **Журнал** хранит каждое изменение: позиции, мероприятия, команду, комплекты, недостачи. «История» в карточке позиции — только по ней.
- **CSV** открывается в Excel (разделитель `;`, UTF-8). Это же — резервная копия; ещё можно Supabase → Table Editor → Export to CSV.
- **Свои категории / статусы** — массивы `CATS`, `STATES`, `STATUSES`, `UNITS` в начале `app.js`.
- **Бесплатный Supabase** засыпает, если неделю никто не заходил; разбудить — кнопка Restore в панели.
- **Удалить сотрудника**: обычно достаточно роли «Ожидает»; совсем — Supabase → Authentication → Users.
