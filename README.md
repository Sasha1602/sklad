# Склад проката

Сайт для учёта прокатного оборудования: вход по почте, роли сотрудников, изменения видны всем сразу, журнал «кто что поменял».

- **Сайт** — обычные файлы (`index.html`, `style.css`, `app.js`, `config.js`), хостится на GitHub Pages бесплатно.
- **База и вход** — [Supabase](https://supabase.com), бесплатный тариф. Права проверяет сама база, поэтому их нельзя обойти через браузер.

## Роли

| Роль | Что может |
|---|---|
| Ожидает | Зарегистрировался, ничего не видит, пока админ не назначит роль |
| Просмотр | Видит склад, мероприятия и журнал |
| Кладовщик | Меняет количество факт, состояние, статус, примечание; отгружает на мероприятия и принимает возврат |
| Менеджер | Добавляет, редактирует и удаляет оборудование и мероприятия, бронирует оборудование |
| Администратор | Всё то же + назначает роли (вкладка «Пользователи») |

**Первый зарегистрированный пользователь автоматически становится администратором.** Поэтому зарегистрируйтесь первым сами, сразу после настройки.

## Установка (≈15 минут)

### 1. Создайте базу в Supabase

1. Зарегистрируйтесь на <https://supabase.com> → **New project**. Имя любое, пароль базы сохраните, регион — ближайший (например, Frankfurt).
2. Дождитесь, пока проект создастся (1–2 минуты).
3. Слева **SQL Editor** → **New query** → вставьте всё содержимое файла `supabase/schema.sql` → **Run**. Должно быть «Success».
4. **New query** → вставьте `supabase/02_events.sql` → **Run** (мероприятия и календарь).
   Затем так же `supabase/03_crew.sql` (команда на выезд) и `supabase/04_schedule.sql` (графики сотрудников), затем `supabase/05_kits.sql` (комплекты).
5. Ещё раз **New query** → вставьте `supabase/seed.sql` → **Run**. Это ваши 64 позиции из инвентаризации 21.10.2026. Запускайте **один раз**, иначе позиции задвоятся.

### 2. Настройте вход

1. **Authentication → Sign In / Providers → Email** — включено по умолчанию.
   - «Confirm email» включён: новым сотрудникам придёт письмо для подтверждения почты. Если хотите без писем — выключите (тогда регистрация сразу пускает на экран «ждём одобрения»).
2. **Authentication → URL Configuration** — заполните после шага 4, когда будет адрес сайта:
   - **Site URL**: `https://ВАШ-ЛОГИН.github.io/ИМЯ-РЕПОЗИТОРИЯ/`
   - **Redirect URLs**: добавьте тот же адрес.
   Без этого ссылки из писем (подтверждение, сброс пароля) будут вести не туда.

### 3. Впишите ключи в `config.js`

В Supabase: **Project Settings → API** (или кнопка **Connect** сверху).

- **Project URL** → в `SUPABASE_URL`
- **anon public** ключ (или **publishable** ключ, начинается с `sb_publishable_`) → в `SUPABASE_KEY`

```js
window.SKLAD_CONFIG = {
  SUPABASE_URL: "https://abcdefgh.supabase.co",
  SUPABASE_KEY: "eyJhbGciOi...",
  TITLE: "Склад проката"
};
```

Этот ключ публичный, его можно выкладывать на GitHub. **Ключ `service_role` / `secret` не вставляйте никогда** — он обходит все права.

### 4. Выложите на GitHub Pages

1. На <https://github.com> → **New repository**, например `sklad`. Можно Public (данные всё равно закрыты паролями и правами в базе).
2. **Add file → Upload files** → перетащите `index.html`, `style.css`, `app.js`, `config.js` (папку `supabase` и README можно тоже, они не мешают) → **Commit**.
3. **Settings → Pages** → Source: **Deploy from a branch**, Branch: **main**, папка **/ (root)** → **Save**.
4. Через 1–2 минуты сайт будет по адресу `https://ВАШ-ЛОГИН.github.io/sklad/`. Вернитесь к шагу 2.2 и впишите этот адрес.

### 5. Первый вход

1. Откройте сайт → **Регистрация** → вы становитесь администратором.
2. Сотрудники регистрируются сами по той же ссылке и попадают в «Ожидает».
3. Вкладка **Пользователи** → выберите каждому роль. У сотрудника страница откроется сама.

## Мероприятия и календарь

1. **Создать** (менеджер): «Мероприятия» → «+ Мероприятие» или кнопка под выбранным днём календаря. Даты — от монтажа до демонтажа: на все эти дни оборудование бронируется.
2. **Выбрать оборудование**: для каждой позиции видно «свободно X из Y» с учётом других мероприятий в эти даты. Если не хватает — карточка подсветится и покажет, на каком мероприятии занято.
3. **Отгрузить** (кладовщик): «Отгрузить» → проверить, сколько реально погрузили → подтвердить. Мероприятие становится «На выезде», на складе у позиций появляется «N на выезде».
4. **Принять возврат**: «Принять возврат» → пересчитать → подтвердить. Всё, что не вернулось, остаётся красным в карточке.
5. **Команда** (менеджер): в карточке мероприятия «+ Человек» — сотрудник с аккаунтом или человек без аккаунта (имя, телефон). Роль на выезде: свет, звук, водитель… Если человек в эти даты уже на другом мероприятии — строка подсветится.
6. **«Только мои»** — галочка над календарём: показывает мероприятия, где вы ответственный или в команде.
7. **«Копировать список»** — команда с телефонами и оборудование по кейсам и стеллажам, готово для мессенджера.

Ссылку на конкретное мероприятие можно отправить коллеге: адрес вида `…/sklad/#ev-12`.

## Графики сотрудников

Вкладка **«Люди»** (менеджер и администратор) → «График» у сотрудника, либо сам сотрудник — клик по своему имени вверху.

- **Основная работа по сменам**: сколько дней работает, сколько отдыхает, и дата любой смены. Например, «сутки через трое» — 1 и 3.
- **Исключения**: «отпуск на основной работе» — смены в этот период не считаются, человек свободен; «недоступен» — занят совсем.
- Таблица **«Кто свободен»** на 3 недели: смены, отпуска, мероприятия. Красная клетка — человек стоит на мероприятии в день смены.
- При добавлении в команду в списке сразу видно, кто свободен, а кто на смене; в карточке мероприятия конфликт подсвечивается.

## Сегодня, комплекты и QR

- **«Сегодня»** — открывается первой: что требует внимания, что уезжает сегодня и завтра, что на выезде и когда вернётся, что не вернулось, кто сегодня работает, что в ремонте.
- **Склад → Комплекты** — кейсы и наборы с постоянным составом. «Взять всё из места…» заполняет состав из места хранения. В мероприятии кнопка «+ Комплект» добавляет весь состав и показывает, сколько таких комплектов свободно на даты.
- **Склад → QR-этикетки** — отметьте позиции или комплекты, выберите лист наклеек (А4 на 24 / 40 / 65) и нажмите «Печать». «По количеству» печатает наклейку на каждую единицу.
- **Сканирование**: при отгрузке и возврате — «Обнулить и считать сканером» → наводите камеру на наклейки. Наклейка комплекта засчитывает весь его состав. Без камеры — впишите код с наклейки (I-12, K-3). Наклейка, отсканированная обычной камерой телефона, открывает карточку позиции на сайте.
- Камера работает в Safari и Chrome; во встроенных браузерах мессенджеров может не работать.
- Чтобы сканер не зависел от зарубежных CDN, положите в папку `vendor` файл `jsQR.js` (скачать: https://cdn.jsdelivr.net/npm/jsqr@1.4.0/dist/jsQR.js). Генератор QR (`vendor/qrcode.js`) уже в комплекте.

## Обновление уже работающего сайта

Загрузите в репозиторий новые `index.html`, `app.js`, `style.css` (через Add file → Upload files, они заменят старые). **`config.js` не заменяйте** — в нём ваши ключи. Новые SQL-файлы из папки `supabase` запускайте в SQL Editor один раз.

## Полезно знать

- **Security Advisor** в Supabase не должен показывать предупреждений. Если базу создавали старой версией `schema.sql` и видите «Can Execute SECURITY DEFINER Function» — один раз запустите `supabase/fix_security.sql`.

- **Журнал** хранит каждое изменение: кто, когда, что было → что стало. Кнопка «История» в карточке позиции показывает только её.
- **CSV** открывается в Excel (разделитель `;`, кодировка UTF-8).
- **Добавить свою категорию / статус** — массивы `CATS`, `STATES`, `STATUSES`, `UNITS` в начале `app.js`.
- **Бесплатный Supabase** засыпает, если неделю никто не заходил; разбудить можно в панели Supabase (кнопка Restore). Если сайтом пользуются регулярно — не заснёт.
- **Резервная копия**: Supabase → Table Editor → `items` → Export to CSV, или кнопка «Скачать CSV» на сайте.
- **Удалить сотрудника совсем**: Supabase → Authentication → Users → удалить. Обычно достаточно поставить ему роль «Ожидает».
